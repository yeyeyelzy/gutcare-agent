## 静态跳转观察及缺陷

以下仅基于 ZIP 中的事件委托、模板目标和页面数组静态审阅，不表示实际运行或点击验证。

- 可见入口包含四项底栏“今日/记录/分析/我的”、今日快捷记录、五类记录分类、分析与历史报告入口、详情返回按钮。正式 APP 路由仍按 `docs/UI原型审查与页面导航规范.md` 注册并用认证守卫控制，不复制数字 hash 路由。
- 缺陷一（运动记录→欢迎页）：第 14 页（index 13）发起综合分析中的运动记录条目把 `page` 设为 `null`；模板用 `p !== undefined` 判断，于是生成 `data-page="null"`。`render()` 将非数字索引归一到 0，目标实际变成第 01 页欢迎页；预期目标是第 19 页（index 18）运动记录。
- 缺陷二（AI 助手排便入口→趋势）：助手回答中的“查看近 7 天排便记录”调用 `link(..., 5)`，目标是第 06 页健康趋势（index 5），不是第 12 页排便记录（index 11）。
- 缺陷三（Tab 栈与认证回退）：每次切换不同底栏根页都将旧页压入一个共享返回栈，跨 Tab 返回会进入前一个 Tab 的页面；栈空时 `goBack()` 固定回第 02 页首页（index 1），登录页也可触发此回退。正式 APP 应保持各根 Tab 栈隔离，认证流程不得回退到受保护首页。

另外，建档页“保存并进入首页”直达第 02 页，并采集正式注册 DTO 不接受的姓名、性别、年龄和报告；这是单独记录的认证/契约冲突，不能当作上述三项导航缺陷之一。正式流程遵循邮箱 + 密码及注册页 22（index 21）到开始建档页 17（index 16）的冻结契约。

## 契约冲突与导入禁令

- 登录原型显示“手机号/邮箱”，注册使用手机号；正式契约固定邮箱 + 密码，不增加手机号、SMS 或短信验证码。
- 注册建档原型收集姓名、性别、年龄和报告上传；冻结注册字段为邮箱、密码、出生年份、隐私政策版本及健康数据处理单独同意。报告登录后经 F02 上传。
- AI 助手原型不构成自由对话契约。APP 只访问业务后端；Agent 是独立服务，只读取任务冻结快照，不能写业务表。
- 禁止复制原型 `localStorage` 持久化、拼接用户内容写入 `innerHTML`、数字 hash 路由、演示数据、模拟保存/登录和演示业务逻辑。
- 唯一归档 SVG 通过固定内容 SHA-256 allowlist 限定，导入脚本只接受这份冻结字节，不提供通用 SVG 上传器。SVG 的标签/引用检查用于纵深验证，不替代来源许可确认。

## 提取、校验与生产门禁

校验已提取资产：`pwsh -File app/scripts/freeze-ui-assets.ps1 -ValidateOnly`。提取时必须显式传入 `-SourceZip <zip文件路径>`；脚本不把调用者绝对路径写入清单。校验核对固定六项 allowlist 与 manifest 双向一致、每项内容哈希/尺寸、资产数与唯一性，并拒绝隔离目录中的额外文件。

门禁扫描 APP 工程、工作流/脚本构建配置及 APP 构建产物，任何 `design-reference` 路径段、目录 glob、资产文件名、内容 SHA 或已提取图像内容引用都会失败。扫描跳过目录按路径分隔符边界匹配；冻结脚本只按完整文件路径精确跳过。当前素材只放在 `design-reference`，不参与 APP 构建。资产要获得授权后仍须经单独审查，再显式晋升到受控生产资产目录并更新门禁；本清单不能自行授权。

manifest 序列化先把 JSON 换行统一为 LF、去除尾部 CR/LF，再使用 UTF-8 无 BOM 写出并追加唯一一个 LF；该算法使 PowerShell 在 Windows 与 Unix 环境生成相同字节。
