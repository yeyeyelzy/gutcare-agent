# GutCare Agent 医疗安全规则规范

> 版本：V1.0 · 2026-10-14  
> 状态：工程框架已冻结；生产临床规则尚待具备资质的医学专业人员审核。

## 1. 边界

规则引擎用于把已记录的危险征象映射为“关注/尽快就医/紧急就医”提示，不进行诊断、处方或剂量决策。规则独立于大模型并在核心记录提交后同步或高优先级执行。

## 2. 规则对象

```json
{
  "rule_code": "GI_BLEEDING_CANDIDATE",
  "version": 1,
  "lifecycle": "draft",
  "environment": "test_only",
  "severity": "emergency",
  "input_schema_version": "1.0",
  "condition": {"all": []},
  "message_template_key": "risk.generic.seek_emergency_care",
  "source_refs": [],
  "review": {"reviewer": null, "reviewed_at": null, "expires_at": null}
}
```

条件 DSL 只允许白名单字段、`all/any/not`、存在性、枚举相等和经审核的数值比较；禁止任意代码、SQL、正则灾难性表达式和模型自由文本判断。

规则事实不是原始 payload：服务层必须投影并再次校验类型，仅允许受枚举约束的 `record_type`、`bristol_type`（1–7）、`blood_reported`（布尔）、`urgency_level`（0–10）、`duration_minutes`（0–10080）、`symptom_codes`（预设类别枚举数组）及 `symptom_severities`（0–10 整数数组）。不允许 `symptom_status`（可由服务端默认）、`notes`、`other_description`、`body_location`、`color_code`、`bowel_amount`、`process_sensation`、`companion_signs`、食物文字或任何任意 payload 字段进入事实。规则若引用未列出的字段（包括这些文本字段），必须显式拒绝执行、产生无患者标识的 critical 配置日志并以 RFC 9457 503 拒绝该次写入；不能静默忽略或按文本匹配。

## 3. 生命周期

`draft → in_review → approved → active → retired`；退回为 `rejected`。只有同时满足 `lifecycle=approved/active`、`environment=production`、审核人/日期/来源/失效日期完整的版本可在生产加载。内容修改必须新建版本，不原地覆盖。

## 4. 候选危险征象（非生产规则）

下列内容仅用于向医学审核者说明候选范围，不构成系统阈值：呕血或咖啡渣样呕吐物、黑色柏油样便或便中明显血液，以及伴意识异常、晕厥/明显头晕等休克表现。NIDDK 建议急性或严重消化道出血症状及时就医，休克表现需立即寻求急救。来源：<https://www.niddk.nih.gov/health-information/digestive-diseases/gastrointestinal-bleeding/symptoms-causes/>

在专业审核完成前，仓库内同类规则必须为 `test_only`，使用明显合成的测试输入，UI 文案仅用于流程验收。

## 5. 执行与去重

- 输入仅用患者明确提交/确认的结构化字段；模型候选不能直接触发生产规则。
- 同一 `patient_id + rule_code + rule_version + source_record_id + source_version` 生成稳定去重键。
- 保存触发字段摘要、规则版本和文案版本，不保存额外推断。
- 记录修改/删除后重新评估；旧提示保留历史并标记依据变化。
- 规则执行失败必须告警，不能静默回退到大模型判断。

## 6. 审核交付物

每条生产规则必须提供适用人群、排除条件、输入定义、严重级别、患者文案、行动建议、权威来源、正反例、边界例、审核人及复审日期。测试至少覆盖真/假、缺失值、冲突值、重复提交、版本替换和智能体不可用。
