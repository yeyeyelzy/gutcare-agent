## 1. 结论与适用范围

- 当前 `compose.phone-demo.yaml` 的默认智能体配置为 `mock`。默认演示不依赖外部大模型 API，也不会向外部模型发送数据。
- live 模式是显式、本机私有、经授权才启用的可选能力；配置文件和访问密钥不纳入版本库。
- 当前仓库不随代码交付外部临床数据集。演示应使用仓库内生成的合成样例或已获授权的本地测试材料，禁止使用真实患者资料。

## 3. 第三方模型与外部 API

### 3.1 接入方式

智能体通过 OpenAI 兼容的 HTTP 接口调用模型。接口地址、模型标识和密钥均由本机私有环境变量提供，代码仓库、日志和文档不保存实际值。支持的模式包括：

- `mock`：默认模式，使用本地确定性模拟结果，不访问外部模型；
- `live`：仅在已配置模型端点、模型名、密钥且用户已授权第三方 AI 处理时启用；
- `replay`：代码可读取先前保存的调用缓存以复现路径；当前仓库不随交付物提供该缓存。鉴于缓存可能包含模型响应，处理健康数据时不得启用或提交此类缓存。

`agent/.env.example` 中列出的 SiliconFlow、阿里云百炼兼容模式、智谱兼容模式和本地 Ollama，仅是可选 OpenAI 兼容配置示例，不表示当前默认启用、长期采购、生产批准或对任何模型效果的背书。

### 3.2 数据流与最小化原则

1. 业务服务先校验健康数据处理授权与第三方 AI 授权；未授权时不创建外发任务。
2. 智能体只能读取任务创建时冻结的输入快照，不能直接写业务表。
3. 图像或文本处理得到的是**候选值**；只有用户在客户端逐项确认后，业务服务才可写入患者记录。
4. 记录的业务侧数据仅限任务状态、必要的候选结构、模型路由版本和审计关联信息；不保存访问密钥、完整 prompt、模型原始输出、报告正文或原始图片 URL。
5. 若用户撤回授权，后续处理应停止，并按既定状态机与保留策略处理已创建任务。

### 3.3 当前外部服务状态

| 服务类别 | 默认演示状态 | 可选启用条件 | 生产使用前必须补齐 |
| --- | --- | --- | --- |
| 第三方大模型推理 API | 未启用，默认 mock | 用户明确授权、私有配置有效、任务数据最小化 | 供应商许可/合同、数据处理协议、区域与跨境评估、保留与删除策略、模型版本登记、上线审批 |
| 本地 Ollama 等自托管兼容端点 | 未启用 | 本机部署、网络边界和模型许可已核验 | 模型权重许可、部署安全、资源评估、升级与漏洞管理 |
| Mailpit | 本地启用 | 无需外部账号 | 仅捕获演示邮件，禁止配置真实外发 SMTP |
| Docker Registry / Debian 软件源 | 构建时可能访问 | 首次拉取镜像或系统包时网络可用 | 镜像来源、摘要、供应链扫描与内网镜像策略 |

业务 API、数据库、Redis、MinIO、ClamAV 和本地 worker 均为本项目演示拓扑内组件，不属于对患者开放的第三方业务 API。
