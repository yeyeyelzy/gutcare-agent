# F02 文件与医疗档案实现补充

本文件与已采纳 [ADR-0009](ADR/0009-f02-private-file-workflow.md) 一并作为现行工程契约；若旧版章节仍描述对象存储直传，应以本补充和 ADR 为准。

F03/F04 的 `diet_image`/`stool_image` 继续复用本文件的 `upload_session`、`file_object`、扫描和同源 gateway；文件关联及识别任务由 ADR-0021 定义，绝不通过 `medical_document` 建模。F03/F04 上传授权、图像识别能力与逐项候选确认不改变本文件 F02 报告解析状态机。

## 表与字段

Alembic `0005_f02_files_medical_documents` 增量建立：

| 表 | 用途 | 关键约束 |
|---|---|---|
| `health.upload_session` | 短期上传申请与状态 | 患者 RLS；幂等键按患者唯一；opaque capability 仅存 SHA-256；会话 15 分钟过期；服务端生成 bucket/key |
| `health.file_object` | 通过校验且 clean 的对象元数据 | 患者 RLS；SHA-256、实际长度/MIME、扫描/存储状态；对象位置唯一 |
| `health.medical_document` | 医疗档案元数据 | 患者 RLS；文件与患者复合外键；notes 最多 1000 字；文档类型、处理和解析状态受约束 |
| `health.file_download_grant` | 单对象短期只读 capability | 患者 RLS + 仅匹配 capability hash 的 gateway 读取策略；5 分钟过期；只持久化 token hash |
| `integration.file_deletion_job` | 延迟物理删除补偿 | worker 独占读取/更新/删除；业务角色仅插入；唯一文件任务、due/status 索引 |

用户/患者数据表使用 `ENABLE ROW LEVEL SECURITY` 和 `FORCE ROW LEVEL SECURITY`。文档关联文件及下载授权通过 `(file_object_id, patient_id)` 复合外键防止跨患者绑定。服务端不可将 bucket/key 作为 APP 输入或输出。

## 状态及限制

- 上传：`issued -> uploaded -> completed`；检查失败进入 `failed`；过期会话不得上传或完成。完成幂等，成功重放同一 file object。
- 对象：`available -> deleting -> 已物理删除`。只有格式完整且 ClamAV `clean` 的文件能被创建为 `available`；infected 或扫描器不可用均不得进入 available。
- 文档：`store_only` 对应 `not_requested`；`analyze` 在智能体阶段接入前只记录 `pending`。候选未逐字段确认前不得置 `confirmed`。
- 允许 PDF（最大 20 MiB）、JPEG/PNG（最大 10 MiB），按服务器实际内容校验大小、MIME、魔数、PDF 加密/损坏和图像解码；上传入口还限制 20 MiB 硬上限。
- 删除立即对列表、详情和下载隐藏并标记 `deleting`；七天后 worker 幂等删除对象和业务行；对象删除失败则退避重试。worker 处理阶段使用独立最小权限会话。

## API / 安全 / 错误

权威 OpenAPI 为 [`contracts/openapi/gutcare-v1.yaml`](../contracts/openapi/gutcare-v1.yaml)。包含上传申请/完成、医疗文档 CRUD、下载授权。gateway `PUT/GET /uploads/{capability}` 是同源 HTTPS gateway 能力，path-item server 指向 origin root，不附加 `/api/v1`；客户端只访问此 gateway，不直连 MinIO、不持有 bucket/key。跨患者资源统一 404；错误使用 RFC 9457，包含 401/404/409/413/415/422/429/503。存储或扫描失败不能返回文件可用状态。Uvicorn `uvicorn.access` 原始 URL access log 必须关闭，避免 path capability 泄漏；替代业务日志只记 route template、request id、状态码和耗时。

不记录文件正文、完整下载/上传 URL、capability、JWT 或 query 参数；响应设为 `Cache-Control: private, no-store`。原始对象只在私有 bucket，metadata 仅保存在 PostgreSQL。

## 验收追踪

阶段5A新增 ADR-0011：`analyze` 必须同时有当前 `health_data_processing` 和 `third_party_ai` 授权，并在文档创建时持久化解析请求；`store_only` 仅要求健康数据授权且不创建任务。Worker claim、Agent 冻结输入读取及候选/失败回调每次重验两项授权。第三方 AI 撤回与健康数据撤回同事务失效所有非终态任务，并清除相关候选 excerpt 与 locator。候选只经受限内部契约读取冻结输入和提交，患者必须逐字段决定；决定接口返回 204，同一幂等键及决定摘要重放不新增审计或事实。详细接口和数据库以 ADR-0011、OpenAPI 与 Alembic 0011 为准。T60–T65 为候选/确认切片；后续 ADR-0017/T103 覆盖 A03–A06 outcome 与建议适用性后端，ADR-0018/T104 覆盖 A07 跨报告冲突。4A/4B 后端子范围独立验收见需求追踪矩阵；真实 PG18/MinIO 门禁仍须单独复现。

| 验收项 | 对应测试/证据 |
|---|---|
| 文件大小/MIME/魔数/PDF/图片损坏校验 | `test_file_policy.py`（单元）；PG/MinIO/ClamAV 集成拒绝测试 |
| 真实对象写入、HEAD、读取、SHA-256 和恶意样本拒绝 | `test_postgres18_f01.py::test_f02_real_minio_clamav_upload_document_delete_and_patient_isolation` |
| APP 幂等、complete 重放、患者隔离、grant、删除不可见和补偿物理删 | 同上；服务层和权限测试 |
| 数据库升级/降级与 RLS/外键 | PostgreSQL 18 integration 中 Alembic head round-trip、RLS 和复合外键检查 |
| API DTO、RFC 9457 和禁止对象存储直连 | OpenAPI 契约验证及 API 权限测试 |

只有单元/静态验证通过不构成 F02 集成验收；发布前需运行 `scripts/test-integration.ps1`，确认真实 PostgreSQL 18、私有 MinIO、ClamAV 的 clean/EICAR 流程和权限隔离均通过。

## 隔离 phone-demo 文件服务

`compose.phone-demo.yaml` 仅为 local/test/demo 添加 MinIO 与 ClamAV，不改变正式 `compose.yaml` 语义。`phone-demo-up.ps1` 复用 `compose.integration.yaml` 的固定 MinIO 源构建和 ClamAV 版本，等待扫描器健康后开放 API，并在 MinIO 健康后初始化私有 demo bucket。MinIO 初始化镜像只使用 `.downloads/phone-demo-minio-init-context` 最小构建上下文，避免将仓库根、`phone-demo.env` 和运行时缓存发送给 Docker daemon。MinIO root 密钥只注入 MinIO 服务和一次性 `minio-init` 容器，用于建 bucket、创建应用用户和绑定策略；API 的 `FILES_ACCESS_KEY`/`FILES_SECRET_KEY` 来自 `phone-demo.env` 中单独生成的随机应用凭据。应用策略只允许目标 bucket 的 Get/Put/Delete、版本删除、bucket location 和版本列表，不允许列举其他 bucket 或调用 MinIO 管理 API。初始化容器用无输出探针验证 bucket 对象读写删除及跨 bucket/管理 API 拒绝。APP/API 不获得对象存储管理端地址或 root 凭据。ClamAV 额外加入一个不发布端口的普通 bridge egress network，只用于下载官方签名库；其业务流量仍在 private network。`phone-demo-down.ps1` 默认保留数据库、私有对象和扫描库卷，`-PurgeData` 会删除 phone-demo 项目全部卷。

通过 `scripts/phone-demo-f02-e2e.ps1` 可本机端到端验证合成邮箱注册与健康数据授权、同源 gateway 上传、真实 ClamAV clean、`store_only` 不派生解析任务、档案列表/详情、下载 grant 与 capability 下载及未认证访问拒绝。当前 Android 已有健康档案 UI 并支持 store-only 上传；上述脚本仍是业务 API 文件服务 E2E，不是 Android 上传端到端，也不验证 analyze、Agent 输入/回调或候选确认。它不替代 `scripts/test-integration.ps1` 的 EICAR 与隔离权限验收。脚本不输出验证令牌、JWT、上传/下载 capability 或文件正文。
