# ADR-0008：授权版本绑定与账号注销入口

- 状态：已接受
- 日期：2026-10-15
- 背景：通用授权写入接口不能撤回 privacy_policy；同意文本版本必须与服务端留存的告知摘要一一绑定；账号注销必须立即冻结并可追踪。

## 决策

1. `POST /patients/me/consents` 仅处理 `health_data_processing`、`sensitive_image`、`third_party_ai`、`push_notification`；不接受 `privacy_policy`。privacy policy 撤回唯一入口为 `POST /patients/me/account-deletion`。
2. 每个 consent type 在服务端配置一个当前允许的 `policy_version` 与对应 `notice_summary_hash`。注册中的 privacy/health 两种版本、以及后续授权决定的版本必须与对应配置精确匹配；不匹配返回 `422 VALIDATION_ERROR`，服务端缺少配置属于部署错误，不得回退到任意客户端版本/哈希。
3. 账号注销请求在单个数据库事务内锁定账户、将状态设为 `deactivated`、撤销该账户全部有效 refresh session，并创建唯一 `iam.account_deletion_request`（初始 `pending`）作为可追踪操作。访问令牌也因账户状态失效。数据清理仍由后续工作流在冻结的生命周期期限内执行。
4. 对已有注销请求重复调用领域服务返回同一 operation ID，不创建重复请求；HTTP 端点仍必须先通过有效访问令牌认证，已撤销令牌不可用于重试。
5. 患者资料 PATCH 在取得 `FOR UPDATE` 锁后使用 `populate_existing` 强制刷新 identity map，再比较 `profile_version` 并更新，避免锁前缓存导致丢失更新或错误冲突。

## 后果

- 需要为五种授权目的分别配置允许版本与摘要哈希；上线配置必须成对发布。
- 增加注销请求追踪表及 Alembic 增量迁移；创建请求即立即阻止登录/刷新。
- `privacy_policy` 不再出现在通用授权 DTO 中，APP 必须使用专用注销流程表达撤回。
- PostgreSQL RLS 与真实数据库并发语义仍需 PostgreSQL 18 集成门禁验证。
