# ADR-0022：迁移至原生 Android 客户端

- 状态：Accepted
- 日期：2026-10-19
- Supersedes：ADR-0001（移动端采用 uni-app）

## 背景

现有患者端实现位于 `app/`，采用 uni-app。团队决定改为原生 Android 客户端，以统一客户端开发、调试和验收流程。该决定仅调整客户端平台与工程边界，不修改业务功能、服务端、数据库、OpenAPI 或智能体集成契约。

## 决策

1. 新增原生 Android 工程目录 `android/`，作为唯一活跃的患者端客户端工程。
2. Android Studio 是客户端唯一开发、构建、调试和验收环境。
3. 旧 `app/` 目录保留为只读归档。不得继续在其中开发、修复或维护；需要复用的业务语义、页面事实和契约依据应迁移到 Android 工程或权威文档，不把旧框架实现当作新架构要求。
4. 当前阶段只交付 Android，不开发、不验收 iOS；不以 H5/Web 页面替代原生 Android APP。
5. 后端、业务数据库、OpenAPI、智能体服务及其读写边界保持不变。Android APP 仅通过既有业务 API 访问业务能力，不直连数据库、对象存储管理端或智能体服务。
6. 先使用 Android Studio 模拟器完成开发阶段验收。Android 真机证据作为发布前门禁，不阻断当前模拟器阶段验收；发布前须补齐涉及系统能力的真机验证证据。

## 后果

- Android 原生工程的语言、UI、构建及测试实现以 `android/` 工程配置和后续技术决策为准；本 ADR 不预先指定未评审的具体框架或依赖版本。
- 旧 `app/` 中的组件测试、CLI 构建或 uni-app 双端验收声明不能作为 Android 原生工程的交付证据。
- Android Studio 模拟器验收覆盖当前阶段功能与契约；相机/文件选择器、系统权限、安全存储、通知、键盘、安全区、后台恢复等设备行为应在发布前真机验证。
- 不涉及业务后端、数据库迁移、OpenAPI 或智能体边界变更，因此本决策不要求相应契约或 schema 变更。

## 追踪与执行

阶段、验收门禁、路径、保留边界和证据记录要求见 `docs/Android原生迁移工作准则.md`。受影响的技术方案、开发实施、联调、UI、测试和需求追踪文档须与本 ADR 同步；遇到旧 uni-app/iOS 描述时，以本 ADR 为准并修正文档。
