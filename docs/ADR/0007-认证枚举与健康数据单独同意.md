# ADR-0007：认证错误隐私、刷新令牌族与注册健康数据单独同意

- 状态：Accepted
- 日期：2026-10-15
- 范围：F01 邮箱认证与注册建档

## 背景

V1 冻结设计要求邮箱未验证时返回 `403 EMAIL_NOT_VERIFIED`，但该响应可用于枚举已注册账户；Refresh Token 只定义单令牌撤销，无法在已用令牌重放时可靠撤销后继令牌。注册字段包含 `birth_year`，属于健康信息处理所需的单独同意，但原注册 DTO 只有隐私说明版本，未收集该授权。

## 决策

1. pending-verification、未知邮箱和错误密码统一返回 `401 INVALID_CREDENTIALS`；保留账户状态机内部 `pending_verification`，删除公开错误码 `EMAIL_NOT_VERIFIED`。
2. 每次登录创建独立 `family_id`；轮换后继承 family 并写入 `parent_session_id`/`replaced_by_session_id`。已撤销 refresh token 再次出现时，撤销同一 family 的所有未撤销 session，并统一返回 `401 AUTHENTICATION_REQUIRED`。
3. `/auth/register` 必须接收 `health_data_processing_consent: true` 与 `health_data_processing_policy_version`。该授权与 `privacy_policy` 分别落为独立 `patient_consent` 记录，并使用各自的告知摘要 SHA-256；缺少/拒绝健康数据处理同意时拒绝注册，不创建账户、资料或会话。
4. 实现冻结契约已有的密码重置 request/confirm 路径。request 对存在/不存在邮箱均返回相同 `202 AcceptedOperation`；confirm 的单次令牌重置密码并撤销该账户的全部 refresh session。

## 后果

- `EMAIL_NOT_VERIFIED` 从对外错误枚举移除；调用方以通用凭据失败处理。
- 增加 `iam.refresh_session.family_id`、父/后继引用及 family 索引；使用 Alembic 增量迁移。
- RegisterRequest 增加两个必填字段，属于契约兼容性变化，客户端需同步升级。
- 健康数据授权文本版本随同意记录保存；不以隐私政策接受代替单独同意。
- 本 ADR 不覆盖患者资料/授权 CRUD，也不改变手机号/SMS 范围。

## 验收

- 对不存在邮箱、错误密码、未验证账户返回相同 HTTP 状态与稳定错误码。
- Refresh 成功轮换建立父子关系；并发重放旧 token 后其 family 的后继 token 均不可再用。
- 注册缺失/拒绝健康数据处理同意时不产生患者资料；成功注册写入两种独立同意记录。
- 密码重置 request 不枚举账户；confirm 单次使用并撤销全部 session。
