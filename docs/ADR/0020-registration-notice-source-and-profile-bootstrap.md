# ADR-0020：注册告知单一来源与登录后资料引导

- 状态：已接受
- 日期：2026-10-17
- 范围：F01 注册告知、认证契约、APP 登录后导航与发布门禁

## 背景

注册页需要同时展示隐私政策告知与独立的健康数据处理告知，并把两个版本号提交给后端。若 APP 文案、提交版本及后端配置分别维护，服务端留存的摘要无法证明用户看到的具体版本。现有页面规范还保留了 `/onboarding/profile` 分支，但 P0 注册已强制提交出生年份并在同一事务创建患者资料，后端没有“资料未完成”状态或专用补全接口；保留该分支会让客户端实现一个不可判定的状态。

仓库当前没有经法律审核、可用于真实患者的正式隐私正文。工程制品不得把开发文案伪装为正式法律告知。

## 决策

1. 注册告知使用版本化 JSON 制品作为构建与部署输入的单一来源。制品逐项包含 `consent_type`、`policy_version`、原文摘要、摘要 SHA-256 和四个后端配置值；APP 展示和提交版本、后端部署配置均必须从同一经校验制品派生，不允许在页面中手写另一套版本或摘要。
2. 摘要哈希输入为 JSON 解码后的 `summary` 字符串，将 CRLF/CR 规范化为 LF 后，以无 BOM 的 UTF-8 编码计算 SHA-256 小写十六进制。制品文件本身必须为 UTF-8、LF 且无 BOM。CI 重算两个摘要，并逐项核对 `PRIVACY_POLICY_VERSION`、`PRIVACY_POLICY_SUMMARY_HASH`、`HEALTH_DATA_PROCESSING_POLICY_VERSION`、`HEALTH_DATA_PROCESSING_SUMMARY_HASH`。
3. 仓库只提供 `contracts/consent/registration-notices.json` 开发/测试制品，其 `artifact_classification=development_test_only`、`legal_approval_status=not_approved_for_production`，文案与版本均明确标记非生产。它只能用于合成数据、自动化测试和开发构建，不得向真实患者展示。
4. 生产发布必须由隐私/法律负责人交付同 schema、已批准且版本唯一的生产制品，并完成签核归档。流水线须先通过同一哈希校验，再将四个值注入业务后端并将同一制品编入 APP。后端 `production` 环境缺少任一配置、摘要不是 SHA-256，或版本带 `test`、`dev`、`development` 的工程前缀时启动失败。由于摘要本身不能证明法律审批，生产制品审批记录和 APP/后端构建对应关系仍是外部发布阻断门禁。
5. P0 注册固定为两屏、一次提交：第 22 页收集邮箱、密码、确认密码和隐私告知确认；第 17 页展示独立健康数据处理告知并在同意后收集出生年份；合并为一次 `POST /auth/register`。确认密码不发送，昵称、性别和报告不进入注册 DTO。
6. 注册受理后完成邮箱验证，再使用邮箱和密码登录。登录或冷启动恢复会话成功后，客户端必须调用 `GET /patients/me` 获取资料，然后进入今日页。P0 不存在 `/onboarding/profile` 路由或“资料未完成”分支。若 `/patients/me` 返回 404，客户端进入不可继续的安全错误态：清除会话、不得创建本地假资料或提交猜测字段，并提示重新登录/联系支持及记录 `request_id`；该异常按数据一致性故障告警。
7. 昵称仍可在已认证的资料编辑页通过 `PATCH /patients/me` 设置或清空，不属于注册或首次引导条件。

## 后果

- 开发和测试可以使用可复现告知摘要完成认证联调，但不能据此宣称生产隐私合规。
- APP 实现不再等待后端不存在的资料完成标志，认证状态机更小且可测试。
- 正式上线前必须获得经审核生产文案/版本制品和签核证据；缺失时即使功能测试通过也不得发布。
- 告知文本或处理目的改变时必须产生新版本和新摘要，更新制品、APP、后端配置、测试及发布记录，不能覆盖既有版本。

## 验收

- 校验脚本拒绝 BOM、CRLF、摘要不一致、重复/缺失 consent type、后端四配置不一致以及任何未明确标为测试用途的仓库制品。
- 生产 Settings 对四项配置 fail closed，并拒绝测试/开发版本。
- OpenAPI 与运行时注册请求均拒绝额外字段；`AcceptedOperation.status` 固定为 `accepted`，认证 token 长度约束一致。
- 资料时区写入仅接受可由 IANA `ZoneInfo` 解析的标识，无效值返回 RFC 9457 422。
- 路由和端到端测试证明登录后固定读取 `/patients/me`；404 不进入首页或虚构 onboarding。
