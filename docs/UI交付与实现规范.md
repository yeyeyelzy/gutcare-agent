# GutCare Agent UI 交付与实现规范

> 版本：V1.0 · 2026-10-14

## 1. UI 交付清单

每个页面需交付：设计稿尺寸、组件/变体、颜色与字体令牌、间距/圆角/阴影、图标 SVG、切图倍率、正常/加载/空/错误/离线/禁用/无权限/待确认状态、键盘与滚动行为、Android/iOS 差异、动态字号和读屏说明。仅有理想状态截图不视为可开发交付。

## 2. 页面映射

设计稿以 F01–F13 和路由名标注，例如 `F03_Diet_List`。交付表至少包含：设计节点、路由、API、权限、数据状态、交互说明和验收截图。UI 文案不得改变数据字典中的状态语义。

## 3. 实现规则

- 使用设计令牌与项目组件，不在页面散布硬编码颜色/间距。
- 页面不直接调用 `uni.request/uni.uploadFile`，不读取 Token。
- 所有异步页面明确区分加载、空数据、失败和离线；失败不得显示为空。
- 安全区域、键盘遮挡、返回手势、相机/相册权限和文件上传必须真机验证。
- 高风险提示使用持久卡片/模态及明确行动入口，不只用 Toast 或颜色。
- 图表同时提供文字摘要，不把颜色作为唯一编码。

## 4. 视觉验收

在约定设备矩阵以同一合成数据截图，与设计稿叠图检查；允许差异阈值由 UI 负责人按组件记录。视觉通过不替代交互、无障碍和业务状态验收。设计变更必须保留版本与变更说明，不能直接覆盖已实现节点而无通知。

## 5. 待 UI 到达后的流程

资产校验 → 页面/API 映射 → 令牌和基础组件 → 页面骨架与 Mock → 接真实 API → 状态/弱网/权限 → 双端真机 → 视觉签收。任何缺失状态先使用现有产品语义补齐并回到设计评审，不创造新的业务状态码。
