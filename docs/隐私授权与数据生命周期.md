# GutCare Agent 隐私授权与数据生命周期

> 版本：V1.0 · 2026-10-14  
> 性质：工程基线，不替代上线前法律意见与正式隐私政策。

## 1. 法规与原则

医疗健康信息属于敏感个人信息。系统执行目的明确、最小必要、单独同意、默认私有、可撤回、可删除和可审计原则。依据包括《个人信息保护法》第十九条（最短必要期限）、第二十八至三十条（敏感个人信息及单独同意）和第四十七条（删除），以及《网络数据安全管理条例》的告知与权利响应要求。

## 2. 授权清单

| consent_type | 是否单独同意 | 作用 | 撤回结果 |
|---|---|---|---|
| `privacy_policy` | 否，注册必需确认 | 基础账户和服务履约 | 只能通过账号注销撤回；通用 consent API 不接受此类型 |
| `health_data_processing` | 是 | 处理医疗档案与健康记录 | 停止新分析，基础删除/导出入口仍可用 |
| `mood_data_processing` | 是，F14 独立授权 | 新增和修改心情记录 | 停止新增/修改并取消尚未完成且含心情的分析任务；本人读取/删除权利保留 |
| `mood_ai_sharing` | 是，F14 独立授权 | 将心情记录中的受控等级/标签交给已披露的智能体处理 | 新任务不再含心情；其他健康数据分析仍可继续 |
| `sensitive_image` | 是 | 处理饮食/粪便等敏感图片 | 不再签发给智能体的新 URL |
| `third_party_ai` | 是 | 向已披露的第三方模型处理者发送最小数据 | 后续任务禁用该处理者 |
| `push_notification` | 否，可选 | 系统推送 | 注销推送令牌，保留站内通知 |

同意记录保存政策版本、该授权类型独立的告知摘要哈希、选择、时间、渠道和撤回时间。`POST /patients/me/consents` 只处理 `health_data_processing`、`mood_data_processing`、`mood_ai_sharing`、`sensitive_image`、`third_party_ai`、`push_notification` 六种决定，每次追加新历史，不覆盖既有记录；撤回记录 `granted=false` 且 `revoked_at=decided_at`。privacy_policy 撤回只能使用 `/patients/me/account-deletion`。服务端为各授权目的分别配置当前允许的 policy version 与 SHA-256 摘要，版本不匹配返回 422，不得将客户端任意版本和服务端摘要拼接；不接受客户端提交摘要。目的、数据种类、接收方或期限发生实质变化时重新取得同意。

`GET /patients/me/consents` 仅返回当前认证患者每种授权的最新决定；未决定的类型明确返回 `granted=false` 且版本/决定/撤回时间为空，不含 consent metadata 或摘要哈希。`GET /consent-notices?consent_type=...` 只从服务端当前告知制品提供文本与用途、范围、接收方、撤回效果；制品缺失、环境不允许、版本/hash 与运行配置不一致时返回 `enabled=false` 且不返回可同意版本。新同意必须提交同次读取的 enabled 告知版本。撤回已有有效决定不依赖当前告知可用：患者提交状态中的既有 policy version，服务端在本人授权栅栏内确认最新决定仍有效，并复用原决定已存摘要哈希追加撤回；未决定或已撤回状态不能伪装成撤回。仓库 `contracts/consent/consent-notices.json` 是 development_test_only 工程文案，未获法律/医疗批准，不可用于生产；生产环境必须替换签核制品并同步逐类型 policy version/hash。APP 不得从 ADR 或本地字符串拼装可供同意的告知。

注册时收集 `birth_year` 前必须取得 `health_data_processing` 单独、明确同意，并保存其独立文本版本及对应告知摘要哈希。`privacy_policy` 的注册确认不构成健康数据处理授权；拒绝健康数据处理时不创建患者资料、不持久化出生年份。两种告知不得共用摘要哈希配置。告知单一来源、UTF-8/LF 摘要规范和生产 fail-closed 遵循 ADR-0020；仓库 `contracts/consent/registration-notices.json` 仅是明确的 development/test-only 工程制品，不替代正式隐私正文或法律审批。生产必须使用经签核的同 schema 制品同时驱动 APP 与后端四项配置，签核缺失时阻断发布。

## 3. 数据分类

- S4 高敏：医疗报告、症状、用药、粪便图片、心情等级/标签/备注、智能分析输入输出。
- S3 敏感：邮箱、推送令牌、设备/安全事件。
- S2 内部：任务状态、去标识指标、配置。
- S1 公开：公开产品说明与已审核公共知识。

S3/S4 不得进入普通日志、崩溃附件、分析埋点或测试数据。开发与演示只使用合成数据。

## 4. 生命周期

| 阶段 | 要求 |
|---|---|
| 收集 | 仅收 P0 所需字段；昵称可空，出生年份必填，不收完整生日/身份证/手机号 |
| 使用 | 基于当前授权；智能体仅访问任务快照；文件 URL 短时、只读、任务级 |
| 共享/委托 | 上线前列明接收方、目的、类型、期限与安全措施；签署处理协议并监督 |
| 更正 | 产生新 `record_version`；旧分析保留版本引用 |
| 撤回 | 对未来处理即时生效；不把撤回前的合法处理改写成未发生 |
| 删除 | 立即不可见并排除新分析；单记录 7 天后物理删除；注销 30 天内完成 |
| 备份 | 加密、隔离、仅灾备；最长 35 天轮转，恢复后重放删除清单 |
| 审计 | 去标识安全事件 180 天；不保存患者内容 |

## 5. 源记录与历史结果

删除源记录后，依赖的历史结果默认保留并标记 `basis_updated`，但必须移除原文 excerpt、定位信息和新访问能力，只显示“来源已删除”。这样保留用户已获得的报告，同时不继续暴露已删除原始内容。用户删除历史结果时一并删除其建议、证据正文和关联文件。

F06 医疗文档来源仅保留 `medication_source_ref` 墓碑：随机稳定引用、患者归属、来源类型、原文档 UUID、可空 live UUID、删除时间；不留正文、文件对象定位、医院名等元数据。F02 删除事务在删除文档/文件前将引用转为墓碑，F06 历史计划保留但 DTO 只返回 `source_deleted`，不返回原文档 UUID；患者复合 FK 防止墓碑被跨患者引用。

F08 创建时冻结仅含授权且已确认的最小结构化事实、来源 ID/版本/locator 和快照摘要；不冻结报告正文、文件 URL、自由备注、prompt 或原始模型输出。源数据后续删除不会改写快照摘要，但 Agent 按 task ID 读取时需重新检查授权及来源可用性，不返回已删除来源的正文或文件能力。授权撤回/账户冻结与任务创建使用同一患者事务级 advisory 栅栏；撤回先提交则阻止新任务/新快照，并将既有非终态任务原子取消，迟到回调拒绝。F08 结构化结果按历史结果生命周期保留，证据仅保留受限 source ref；删除来源后 DTO 隐去 locator 并标记来源已删除。

F09 建议另由 `analysis.health_advice/advice_evidence` 保存，F08 result 不直接成为 advice。建议 callback 与当前健康数据、第三方 AI 授权复核共享患者 consent fence。患者证据只引用同一冻结 task snapshot 中精确的来源版本和 locator；来源版本替换/更新/删除后，建议保留历史正文并显示 `basis_updated`，同时清理该来源 locator 与跳转能力。知识库 evidence 仅保存引用标识、版本、标题、发布者与可选 HTTPS citation URL，不保存知识正文或 chunk 原文。患者反馈仅保存结构化类型与变更历史，不收自由文本原因。

F12 站内通知仅保存受控事件类别、优先级、患者归属、受控目标 ID、时间、去重键和已读时间；outbox payload 仅含白名单字段，不复制报告正文、建议内容、药名/剂量、URL/locator、prompt 或原始模型输出。通知详情 target 在读取时验证来源仍存在，删除后只返回 `target_unavailable`。普通提醒偏好不影响 F10 风险生成；冻结账户的通知 API 不能读取通知，注销清理由 F13 生命周期处理。本阶段不接外部 push 或供应商 SDK。

F07 活动记录按患者健康数据处理，使用 FORCE RLS；软删除后即刻从详情、时间线和聚合排除，按单记录 7 天策略物理清理，并随账号注销清除。F11 仅返回类别、时间、状态/计数和跳转 ID；不复制饮食/症状正文或建议正文，不从时间邻近推导因果。

F14 心情记录按 S4 高敏健康数据处理。新增和修改要求 `health_data_processing` 与 `mood_data_processing` 当前有效；本人原始记录列表、详情和删除作为数据主体权利保留。F11 mood 趋势是派生处理而非原始记录读取，需 `health_data_processing` 与 `mood_data_processing` 均有效；任一撤回后，`/trends` 其他指标照常返回，仅 `mood` 子结构置为 `availability=consent_required`，附 `reason_code=CONSENT_REQUIRED` 和 `missing_consents`，不返回 buckets 且不能伪装为零数据；授权有效但范围内无记录时返回 `availability=available` 与空 buckets。该趋势不要求 `mood_ai_sharing` 或 `third_party_ai`，也不发送给 Agent。F08 快照纳入心情字段还要求 `mood_ai_sharing` 与 `third_party_ai` 当前有效。心情数据可以独立选择不共享；其他健康数据分析不依赖 mood 专项授权。快照仅包含等级、受控标签、发生时间和来源 ID/版本/locator，不包含 `note`。授权撤回与任务创建、快照读取共用患者 consent fence；撤回先提交则阻止新增/修改或后续心情输入，取消含心情的非终态任务并拒绝迟到结果将其用于新建议。既有完成结果按历史结果生命周期保留并标记依据状态，不把撤回追溯改写为未处理。心情备注不得进入日志、崩溃附件、错误详情、通知、埋点、指标、F11 趋势、确定性风险规则或 Agent 输入；F11 可为患者本人提供结构化 `mood_level` 的确定性计数/分布，不读取备注与标签。F13 仅在患者显式选择 `mood` 导出类别时，才将本人未删除记录（含备注）写入受 AES-GCM 应用层加密和一次性短时下载保护的归档 `data.json`；未选择时不查询/包含 mood。含 mood 的导出不在 manifest 对 `data.json` 写入摘要或大小，备注不进入日志、错误、对象 key、通知或指标。记录立即软删除隐藏，7 天内物理清理；清理队列只存患者/记录 ID 与到期时间，由独立 privacy worker 以患者 RLS 删除记录及对应幂等账本。注销清理覆盖 mood 记录、其待清理元数据和相关幂等账本；冻结任务快照保持不可变且不反写源事实。注销 inventory 和导出类别纳入 F14 表。

## 6. 账号注销

调用 `POST /patients/me/account-deletion` 后，单事务立即把账户状态改为 `deactivated`、撤销全部 refresh session 和 consent、取消分析/解析任务，并创建独立于账户外键的 `privacy.deletion_operation`。响应只返回一次性高熵 receipt；数据库只存 SHA-256。receipt 用于不依赖活跃登录的进度查询，错误 receipt 与未知 operation 统一常量 404 并限流。账户级唯一活动操作约束合并并发/重复请求。操作带有 30 天 SLA `due_at`；逾期状态进入告警。

`gutcare_privacy_worker` 持独立数据库角色和 MinIO 凭证，使用 lease、逐步骤账本、重试和 dead-letter。请求和每次 claim 均建立对象 inventory，覆盖登记对象、未完成上传、孤儿对象和导出产物。先撤销下载 grants、上传/导出 capabilities 与 callback 接收资格，再删除对象；对象确认删除后清空明文 key，仅留加密摘要。数据清理顺序为 F12→F09→F08→F02 candidates/documents/files→F03-F07/F10/F14→consents/profile/account。全局 `safety.risk_rule` 不删除。完成后 operation 清空 patient ID，仅保留 account hash、operation/status/timestamps、步骤摘要和受限错误码；去标识 security audit 保留 180 天，不记录正文、对象 key 或 token。

导出由患者 API 创建、预览、列出、查看状态、确认和取消，类别采用服务端白名单。异步 worker 生成规范 JSON 与 manifest ZIP。存在 `cryptography` 时使用 AES-GCM 应用层加密并由同源 gateway 经一次性短时能力流式解密；否则使用私有 MinIO SSE 和相同的同源 5 分钟单次能力。不得直连 MinIO。导出不含密码、token、callback、幂等键、内部 locator、prompt、模型原始输出或知识库正文。注销立即撤销导出能力并纳入对象 inventory；短期导出对象到期清理。

备份最长 35 天轮转。恢复后、readiness 开放前必须执行 privacy replay，重放 pending deletion 和对象 inventory；墓碑覆盖至少 35 天，防止恢复数据重新可见。

## 7. 工程验收

- 每个授权类型具备授予、拒绝、撤回和审计测试。
- 删除后列表、详情、下载、智能体输入和缓存均不可访问。
- 跨患者访问统一返回 404。
- 恢复备份后自动应用删除账本，不使已删除数据重新可用。
